# Stage04 DeepDive — 자료구조 (Stack/Queue/LinkedList/Dictionary/Tree/Heap)

## 목표
상황에 맞는 자료구조 선택 + 시간복잡도 감각을 익힌다.

### [S04-01-01] 심화: Stack 내부와 LIFO의 정석 용도
- 내부는 배열+top 인덱스, Push/Pop O(1) (증설 시 분할상환 O(1))
- 정석 용도: Undo/Redo, DFS, 호출 스택, 뒤로가기
- Redo가 필요하면 Stack 2개 (undo/redo 쌍, 새 입력 시 redo 클리어)
- 초급: Undo 동작 확인 / 중급: Redo 스택 추가 / 고급: 명령 패턴(ICommand+스택)으로 행위 Undo 확장

### [S04-01-02] 심화: 무한 히스토리와 메모리
- 상한 없는 기록은 플레이 시간 비례 메모리 증가 (실질적 누수)
- 대책: 개수 상한(본 씬), 시간 상한, 압축(키프레임+델타), 디스크 스필
- 초급: 상한 값 바꿔보기 / 중급: 메모리 프로파일 비교 / 고급: 리플레이 시스템 관점의 기록 설계

### [S04-02-01] 심화: 원형버퍼 (S04_02 Queue_Spawner 연계)
- Queue 내부는 배열+head/tail 인덱스, Dequeue는 head 이동만 (데이터 복사 없음) -> O(1)
- 가득 차면 2배 증설 후 head부터 순서대로 복사 (분할상환 O(1))
- List.RemoveAt(0)은 뒤 원소를 전부 한 칸씩 당김 -> O(n)
- 고정 크기 큐(탄약, 로그 링버퍼)는 직접 원형버퍼 구현: `(head+1)%capacity`
- 초급: Dequeue 순서 확인 / 중급: 원형버퍼 직접 구현 / 고급: 무할당 고정 버퍼 + 오버런 정책(덮어쓰기 vs 드롭)

### [S04-02-02] 심화: Queue의 한계와 교체 기준
- 중간 삭제/인덱스 접근 불가 -> 필요시 List (중간 삭제) / LinkedList (양끝+중간 노드 삭제)
- 우선순위 필요 -> PriorityQueue (S04_06 연계), 취소 필요 -> 취소 플래그+필터 Dequeue
- 초급: 한계 상황 나열 / 중급: 교체 리팩터링 / 고급: 스케줄러 관점의 큐 선택 (FIFO vs 우선순위 vs work-stealing)

### [S04-03-01] 심화: LinkedList 노드 구조
- 각 노드가 값+prev/next 참조, AddLast/Remove는 포인터 2~4개 교체 -> O(1)
- 대가: 노드마다 객체 할당(GC), 캐시 지역성 나쁨(배열 대비 순회 느림)
- 정석 용도: 양끝 삽입/삭제 반복, 중간 삽입/삭제 빈번 + 이미 노드 참조 보유 시
- 초급: 칸 추가/제거 확인 / 중급: List와 삽입 속도 비교 / 고급: 풀링된 노드/커스텀 인트루시브 리스트

### [S04-03-02] 심화: 인덱스 없음의 의미
- n번째 접근이 head부터 순회 -> O(n), `list[i]` 같은 랜덤 액세스 불가
- foreach 순회 중 수정(삭제)은 InvalidOperationException -> 삭제할 노드 미리 수집 후 처리
- 초급: foreach 중 삭제 예외 재현 / 중급: 안전한 삭제 패턴 / 고급: 스냅샷 순회 vs 버전 카운터 설계

### [S04-04-01] 심화: 해시테이블 원리
- 키->해시->버킷 인덱스, 충돌은 체이닝/오픈어드레싱으로 해결, 평균 O(1)
- string 키는 GetHashCode+Equals 비용, 프레임당 수천 회 호출 시 int/enum 키 고려
- GetHashCode 변경 가능한 키(가변 객체)는 금지, Dictionary 순서는 보장 없음
- 초급: O(1) 체감 실험 / 중급: 키 타입별 비용 비교 / 고급: 커스텀 IEqualityComparer와 해시 분포

### [S04-04-02] 심화: TryGetValue와 예외 설계
- 인덱서 미스 = KeyNotFoundException, ContainsKey+인덱서 = 해시 연산 2회
- TryGetValue 1회로 존재+값 동시 획득, GetValueOrDefault(C# 최신)는 읽기 전용 간편식
- 0개 정리(Remove)는 메모리+순회 비용 절감, 빈번한 추가/삭제면 Clear+재사용
- 초급: 예외 재현 / 중급: 호출 횟수별 패턴 정리 / 고급: 실패율을 고려한 Try 패턴 API 설계

### [S04-05-01] 심화: 트리 표현 방식 비교
- 참조 연결(본 씬): 직관적, O(깊이) 탐색, 직렬화/저장 시 변환 필요
- 평탄 List+parentId: 저장/네트워크 전송 용이, 조상 탐색은 전수 조사 (인덱스 보조 시 완화)
- 완전이진트리는 배열 표현 가능 (힙이 그 예, S04_06 연계)
- 초급: 두 방식 작성 / 중급: 저장/불러오기 구현 / 고급: ScriptableObject 그래프 + 에디터 시각화

### [S04-05-02] 심화: DFS vs BFS
- DFS(본 씬): 깊이 우선, 재귀 간결, 깊은 트리에서 스택오버플로 위험
- BFS: 너비 우선, Queue 사용, 최단 해금 경로 탐색에 유리
- 반복 DFS(명시적 Stack)로 재귀 위험 제거 가능 (S04_01 연계)
- 초급: DFS 순서 출력 / 중급: BFS로 재작성 / 고급: 위상 정렬(선행 스킬 그래프가 DAG일 때)

### [S04-06-01] 심화: 힙(heap) 내부 동작
- 완전이진트리를 배열(List)에 저장, 부모-자식 힙 속성 유지 (최소힙: 부모 <= 자식)
- Enqueue: 맨 뒤 삽입 후 위로 올림(sift-up) O(log n), Dequeue: 루트 꺼내고 맨 뒤를 루트로 내림(sift-down) O(log n)
- .NET 표준 PriorityQueue<T>는 Unity 6000(.NET Standard 2.1) 컴파일 환경에서 미지원 -> 본 씬은 MinHeap 직접 구현 (동일 복잡도, API는 Enqueue/Dequeue/Clear)
- 매번 전수 Sort O(n log n) 대비 상위 k개만 필요할 때 유리, 전체 정렬 출력은 Sort가 단순
- 초급: Dequeue 순서 확인 / 중급: 힙 직접 구현 / 고급: k-최근접/어그로 스케줄러 설계

### [S04-06-02] 심화: 우선순위 설계와 갱신 전략
- 우선순위=거리 단일 축이 단순, 실전은 거리+HP+위협도 가중합
- 본 씬 MinHeap은 우선순위 변경(키 감소) 미지원 -> 스캔마다 재구축, 또는 꺼낼 때 null 검증(lazy deletion)
- 스캔 주기(0.5초)는 정확도-비용 트레이드오프, 타겟 고정(스티키)으로 떨림 방지
- 초급: 주기 바꿔보기 / 중급: 가중 우선순위 / 고급: 공간 분할(쿼드트리)과 힙의 조합
