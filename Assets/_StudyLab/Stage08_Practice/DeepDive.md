# Stage08 Practice DeepDive

## [S08-01-01] 심화: Singleton의 빛과 그림자
- 빛: 전역 접근 1줄, 씬 전환 생존(DontDestroyOnLoad) 관리 용이. 매니저/세이브/오디오에 적합.
- 그림자: 숨은 의존성(테스트 시 가짜로 교체 불가), 순서 의존(초기화 타이밍), 멀티씬 중복 생성.
- 대안: 필요 범위가 좁으면 SerializeField 주입, 테스트가 중요하면 인터페이스 + DI. 판단 기준을 익히는 게 학습 목표.

## [S08-01-02] 심화: event Observer 패턴
- 발행자(Health)는 구독자가 누군지 모른다. 결합 방향이 한쪽으로만 흐른다.
- `Action<int>`에 현재값을 실어 보내면 구독자가 재조회(polling)할 필요가 없다.
- 실수 포인트: 씬 전환/파괴 시 `-=` 해제 누락 -> 파괴된 객체 호출(MissingReference) 또는 누수. OnDisable에서 해제 습관.

## [S08-01-03] 심화: State 패턴과 전이표
- 이 데모는 enum + Tick 방식(경량 상태머신). 상태가 3~4개면 충분하고 읽기 쉽다.
- 상태가 6개 이상 + 전이 조건이 복잡해지면 클래스 분리형(State 객체 + 전이표)으로 격상.
- 전이 규칙을 Tick/Change 한 곳에 모으는 게 핵심. Update 곳곳에 흩어진 `if(state==)`가 스파게티의 시작.

## [S08-01-04] 심화: Factory와 OCP
- 개방-폐쇄 원칙: 새 적 추가 시 스폰 호출부는 수정 없이, 팩토리 내부만 확장.
- 문자열 키(`"Boss"`)는 오타에 약하다. 실무에선 enum/ScriptableObject 키로 격상.
- 팩토리가 커지면 등록식(딕셔너리<string, Func>)으로 전환. 이 파일은 학습용 최소형.

## [S08-01-05] 심화: Command와 Undo
- 요청(무엇을, 얼마만큼)을 데이터 + 실행기로 묶어 스택에 쌓는다. 되돌리기는 역연산.
- 입력 리플레이(녹화/재생), 네트워크 동기화(커맨드 전송), AI 행동 큐가 같은 구조.
- 한계: 역연산이 항상 존재하지 않음(파괴/소모). 그 경우 스냅샷(Memento) 방식과 조합.

## [S08-02-01] 심화: JsonUtility 직렬화 규칙
- 저장 대상: public 필드 또는 [SerializeField] private. 프로퍼티는 무시.
- 미지원: Dictionary, 다차원 배열, null 다형성. 우회책은 List 래퍼 + 타입 태그.
- `prettyPrint=true`는 디버깅용. 릴리스 저장소는 용량을 위해 false 권장.

## [S08-02-02] 심화: 2단 저장 설계
- 1단 PlayerPrefs: 동기/간편/소용량. 슬롯·설정 저장에 적합. 암호화 없음에 유의.
- 2단 파일(persistentDataPath): 백업·공유·외부 편집 가능. 플랫폼별 경로 추상화가 덤.
- 폴백 순서(Load 참조): 빠른 층 -> 영속 층. 쓰기는 양쪽 동시. 삭제도 양쪽 동시. 불일치가 버그의 온상이라 순서를 고정.

## [S08-03-01] 심화: 왜 순수 로직인가
- UnityEngine 의존 = 테스트에 에디터 Play 필요 = 느리고 깨지기 쉬움.
- 순수 클래스 = `dotnet test`/EditMode에서 수 ms 만에 수백 케이스 실행.
- 경계선: MonoBehaviour는 입력·표시·생명주기만, 판단·계산·규칙은 순수 클래스. 이 분리가 테스트 커버리지의 출발점.

## [S08-03-02] 심화: 테스트 2건의 의도
- `AddBeyondCapacity_Fails`: 경계값 테스트. 용량 정책이 깨지면 인벤토리 경제 붕괴.
- `RemoveMissing_ReturnsFalse`: 없는 것 삭제 시도. 예외 대신 false 계약. 조용한 실패 vs loud 실패의 설계 선택.
- 다음 단계: 경계(0/1/가득 참), 중복 획득 스택, 슬롯 해제 후 재사용. Given-When-Then으로 케이스 확장.

## [S08-04-01] 심화: 체크리스트 항목별 근거
- 씬 등록 누락: 가장 흔한 빌드 후 빈 화면 사고. Addressables 전환 전엔 특히 필수.
- Bundle Identifier: 스토어·푸시·SDK 연동의 키. 중간 변경 시 재설정 지옥.
- IL2CPP/아키텍처: 네이티브 크래시는 로그 추적이 어려워 사전 확정이 싸다.
- Strip Engine Code: 용량 이득 vs 리플렉션/JsonUtility 코드 스트립 리스크. 링크 파일 검토.

## [S08-04-02] 심화: 에디터 분기 안전 패턴
- `using UnityEditor;`는 에디터 어셈블리에만 존재. 빌드 포함 시 컴파일 에러.
- `#if UNITY_EDITOR` 블록 안에만 에디터 API를 두고, using도 블록 안에 배치하거나 사용 금지.
- 이 스크립트는 한 걸음 더 보수적으로 using 자체를 없앰. 자동화(빌드 파이프라인)는 별도 Editor 폴더 스크립트로 분리하는 게 정석.
